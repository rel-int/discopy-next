# cubic-round

```bash
python3 -I .claude/skills/cubic-round/threads.py <pr> [--all] [--reviews] [--todo FILE] [--repo o/r]
```

Read-only REST with `$GITHUB_TOKEN`. Header lines:
- `#N <state> head=<sha> <title>`
- `cubic: last review <STATE> on <sha>` then `= head`, `only merges since` (cubic skips
  merge-only pushes, so the review is current), or `N code commit(s) since, not re-reviewed yet`
  (cubic re-reviews a code push by itself within minutes; to force a round,
  `mcp__github__add_issue_comment` with `@cubic-dev-ai review` plus the footer below).
- `reviews:` each reviewer's latest non-empty review, `login STATE@sha`.
- `threads: T, unresolved U, on us W`.

Then each unresolved thread: `<n>. path:line [author] thread-root-id=<id> [outdated] [addressed <sha>]`.
A thread on us (its author spoke last, or a bot's thread answered but not resolved, flagged
`[answered, resolve it]`) comes with its root body (`[P1]`–`[P3]` is cubic's severity, a
`suggestion` block kept) and one `↳ login: …` line per reply. A human's answered thread is
the header alone, `[answered, waits on <login>]`: it stays open. `--all` prints every thread
in full, resolved too; `--reviews` adds the review summaries.

## A round

1. Nitpicks need no TODO.md: fix, push, reply, resolve. Otherwise start one (RULES.md 2):
   ```bash
   f=$(mktemp) && out=$(python3 -I .claude/skills/cubic-round/threads.py <pr> --todo "$f") &&
   mapfile -t b <<< "$out" &&
   python3 -I .claude/skills/checkboxes/boxes.py start --round --from-file "$f" "${b[@]/#/--box=}"
   ```
   `--todo` writes the quoted feedback to the file and prints one `path:line <gist>` per thread
   whose author spoke last (exit 1 if none).
2. `boxes.py claim N` before each finding. Reproduce it on the branch before believing it.
   - Real: a test that fails first, then the fix; take a `suggestion` only after checking it.
   - False: trace why (the code path, a command and its output).
3. Push the fixes (run next-checks first), `boxes.py done N`, then on each thread:
   - reply with `mcp__github__add_reply_to_pull_request_comment` (`commentId` = thread-root-id):
     the fix and its sha, or the traced reason, ending with
     `\n\n---\n_Generated by [Claude Code](https://claude.ai/code)_`.
   - resolve with `mcp__github__resolve_review_thread`, which takes the `PRRT_…` id: one
     `mcp__github__pull_request_read` (`method: get_review_comments`, `perPage: 100`) lists them,
     each thread's comment `html_url` ending `#discussion_r<thread-root-id>`. Without the MCP
     tool, leave it unresolved and say so.
4. `boxes.py finish` (`--no-changelog` when no user sees the fix), then re-run `threads.py <pr>`:
   cubic approves a code push when it finds nothing.

Edge cases: if the `ccr/review_threads` route fails, threads are rebuilt from `in_reply_to_id`
and the header says resolution is unknown. `>=N code commit(s)` means the PR's 250-commit list
ran out first. Cubic can mark a thread `[addressed <sha>]` while it is still unresolved: reply
and resolve it all the same.
